# Owner v1 验收账本

此表区分离线测试与真实 GPU 任务。只有同一行的业务结果、模型后端证据、Owner 交接和整卡观测都留有记录，才可标为通过。Owner 不保存业务结果，本表也不作为运行状态数据库。

| 场景 | 当前证据 | 真实验收还要证明 |
| --- | --- | --- |
| Core 同时获取与三态恢复 | 假项目并发、重启和故障离线测试通过 | 真实观察端故障后 `UNKNOWN` 禁新任务，旧任务不中断；新鲜事实恢复 |
| H3 普通单阶段视频 | Owner 桥、路由边界、旧链、入口早拒、后台观察器及 Continuum 回归组合独立重跑 138 项 CPU 测试通过；媒体编码器的 GPU0 路径和后台资产分析边界另有 28 项 CPU 回归通过；签名 UNKNOWN／Comfy 门禁异常冻结新阶段和单纯 Coordinator 连接中断继续旧窗口均有回归；Comfy 原始失败 history 格式已核对；重启后已提交复合阶段可按精确 Comfy 终态写回，下一阶段仍须重新取得授权 | 原 H3 API 提交一个完整视频，核对唯一 Comfy prompt、输出、卸载、Owner release 和下一项目准入 |
| H3 Continuum 长视频 | 已接入本地复合任务与关键帧/视频共用窗口；离线回归包含取消不发全局中断、失败格式识别与不盲重投 | 关键帧、多个视频阶段、失败重试和发布共用同一 Owner；取消阻止后续阶段，在跑 prompt 自然终结或经已验证的精确接口取消；终态后一次释放 |
| H3 其他本地 GPU 功能 | 普通独立图片、资产组图、镜头变化、本机音频、放大、WAN 和无稳定请求 ID 的 render 等在 Owner 模式入口前拒绝；旧模式功能仍在 | 根据 H3 实际使用决定逐项接入同一 Owner 窗口与最终门禁；未完成前不能宣称 H3 所有本地 GPU 功能已迁移，也不能在完整切换时让它们绕过 Owner |
| Live 录音和模型任务 | Core、Agent、Worker 的 Owner 路径已写入工作树；独立审计修复了 Worker 预热绕门、凭据传递、共享 Ollama 直连与结果完成竞态。Core 110 项、Event Store 29 项、定向 Worker/Owner/Broker 241 项离线测试通过；完成状态已提交但事件缺失时的恢复有定向回归。现有专用模型目标与共享源文件仍有硬链接且写权限过宽，staging 脚本已改为拒绝此状态并要求独立受限目录；生产模型仍驻留旧 Worker，没有真实任务证据 | H3 持有时录音落盘和 ACK 正常、GPU 阶段等待；释放后原 Core 任务自动继续，Worker 无绕门入口，结果写回在重试与进程崩溃后不重复；专用 Ollama、模型卸载及交接需现场确认 |
| Manga 单页 | Owner 主流程、签名观察、语义与 FLUX 双 Worker 门禁及旧门禁组合重跑 103 项 CPU 测试通过；默认观察器把等待 Owner 的 CPU 业务与真正 GPU 活动分开，补充观察与 CUDA 进程扫描回归 35 项通过；Worker 观察死锁、取消后的计数泄漏、可配置 GPU 标记绕门及残留 Cobra 入口均已离线修复；仍未运行真实页面 | 原创页面真实导入、语义与 FLUX 推理、最终产物可读，所有 Worker 入口受控，模型卸载后交接 |
| H3 → Live → Manga → H3 | 用虚构令牌和模拟直接事实跨三个项目的实际 HTTP 客户端跑通 H3→Live→Manga 等待、获取和释放；无真实 GPU | 每一方向各跑真实任务，检查没有双 Owner、假空闲、假阻断或显存残留 |
| 故障 → UNKNOWN → 恢复 | Core 离线故障测试通过 | 服务中断、观察缺失、Comfy 提交结果不明时，旧任务继续且新任务等待；只靠直接事实恢复 |
| 公网 502 与监控 | 历史日志确认旧 Broker 子进程退出时隧道仍在，导致上游不可达；当前监护进程约 10 秒后重启子进程。原始退出诱因未获证实；公网 `/ready` 当前会转发至本机 Broker，只验证 Broker 与 GPU 遥测就绪 | 留存进程异常退出诊断，复现原失败业务链并跑完对应真实任务；公网监控中断不影响本机 GPU 调用 |

每次真实演练记录项目任务 ID、原后端 ID、开始和终止时间、模型实际结果、Owner 三态及实例、四路直接观察时间、4080 显存/利用率、释放确认和错误日志类别。不得把 `/health`、构建通过或仪表盘显示当作业务验收。

切换门槛：三项目全部 GPU 入口封闭且空闲、模型卸载、后台自动恢复暂停并核实，实测整卡交接范围后创建本机 `owner.json`；首次 Owner 启动先 `UNKNOWN`，三项目直接观察确认 `FREE` 后才允许恢复业务取队列。任何一项缺证据时维持旧生产链和共享门禁关闭。
